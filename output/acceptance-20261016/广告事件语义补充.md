# 广告事件语义核查

核查日期：2026-10-16。此说明纠正验收快照中将 FAILED 直接概括为“开屏广告故障仍在线上发生”的表述。

- APP_ENTRY 是进入前广告场景。本次 REWARDED 表示后台配置的进入前激励广告，不代表独立的开屏广告 SDK 类型。
- 健康接口统计客户端上报的 FAILED 行，不主动检测 TikTok 广告，不按用户未看满 N 次生成 FAILED。后台轮询不生成事件。
- CLOSED_INCOMPLETE 是未完整看完关闭；CLOSED_COMPLETED 是完成回调被服务端确认。两者与 FAILED 含义不同。
- 旧客户端 ad.show() 的拒绝、SDK onError 和 SHOWN 上报异常进入同一错误处理器。普通 SDK 错误对象还会丢失 code/message，统一存为 ENTRY_AD_SHOW_FAILED。仅凭历史通用码不能区分无填充、频控、网络等原因，也不能证明某条一定来自上报误分类。
- 自动重试间隔从 500ms、1000ms 开始，多用户、多会话汇总会出现密集记录。每条 FAILED 不代表一个独立用户。
- 实际样本：TaleTV 同会话、第 2 次广告，在北京时间 14:17:35.775 有 FAILED，后续重试于 14:18:07.883 有 SHOWN。仅证明后续有展示上报，不能证明属于用户本人、看完全部广告或最终进入成功。
- createdAt 是服务端入库时间；完成接口会更新原 SHOWN 行而保留该时间，不能据此计算真实播放时长。

本次本地修改将 SHOWN 上报异常独立记录为 API / ENTRY_AD_SHOWN_REPORT，不再生成广告 FAILED，并补充后台事件口径说明。小程序 32 项测试及小程序、后台 TypeScript 检查通过。此修订尚未上传 Portal，不会追溯改变旧包日志，也不代表已修复 TikTok SDK 的实际广告供应问题。原验收目录内 ZIP 构建早于本修订，未包含这次误分类修复。

现有 TaleTV 所核对策略为 onUnavailable=ALLOW，连续广告不可用时存在放行例外，与“任何情况下必须看满”不同。本次未修改策略。
