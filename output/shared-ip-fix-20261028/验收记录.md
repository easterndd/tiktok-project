# 2026-10-28 服务器 CPU 与接口稳定性修复验收

## 结论

本次确认并处理了两个后端瓶颈：

1. `SharedIpAddress` / `SharedIpVisit` 的主键索引存在，但 Prisma 把字符串参数绑定为 PostgreSQL `text`，导致部分主键比较不能使用 `CHAR(64)` 索引。修复后生产 `EXPLAIN` 显示主键 `Index Scan`，热点表的扫描行计数不再增长。
2. HeartReel 的入口广告 `/shown` 事务等待超时与 PgBouncer 池容量相符。原池每个应用 3 个基础连接，备用池要排队 3 秒才启用；Prisma interactive transaction 默认最多等待 2 秒，因此会先报 P2028。PgBouncer 参数已调整为每个应用 4 个基础连接、2 个备用连接，备用池 1 秒启用，全局用户连接上限 60。

API 及 PgBouncer 均已部署并通过健康检查。稳定窗口最近 60 秒没有 HTTP 5xx。广告 SDK 的 `ENTRY_AD_PLAYBACK` 事件仍存在，不属于这两项后端修复能消除的问题。
