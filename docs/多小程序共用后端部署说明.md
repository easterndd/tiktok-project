# QuicK ReeLS 与 TaleTV 重新部署

内部标识统一为 `taletv`：包路径 `apps/taletv`、API `/api/taletv/v1`、服务端环境变量 `TALETV_*`、管理后台构建变量 `VITE_TALETV_*`。QuicK ReeLS 继续使用 `/api/v1`。两个小程序使用独立 PostgreSQL schema 或数据库，共用 BytePlus 账号和可选共享平台数据库。

先从本机把本次 Git 提交推送到远端 `main`（`git push origin main`），再在服务器执行以下命令。先确认当前部署使用哪个 Compose 文件；示例用自托管 PostgreSQL 的 `compose.production.self-hosted.yml`。如果使用托管 PostgreSQL，将 `COMPOSE` 换为 `compose.production.yml`，数据库备份/改 schema 步骤使用你自己的数据库管理连接完成，不要直接把含 `?schema=` 的 Prisma URL 交给 `psql`。以下 Docker 命令使用 `sudo`，适用于 `ubuntu` 用户没有 Docker socket 权限的服务器。

## 1. 拉取与停服务

```bash
cd /opt/quickreels
git status --short
git fetch origin main
git merge --ff-only FETCH_HEAD
git rev-parse --short HEAD
export COMPOSE=compose.production.self-hosted.yml
sudo docker compose --env-file .env.production -f "$COMPOSE" stop api worker admin
```

服务器若处于 detached HEAD，上述 `fetch` 加快进合并仍可更新当前提交；确认 `git rev-parse` 输出是本次提交后再停服务。若有未提交改动或快进合并失败，先处理该状态，不要使用 `git reset --hard`。停止 API 和 worker 是为了避免 schema/共享授权数据改名期间写入。原 `/api/xu03/v1` 路径不再提供服务，完成本次部署后须重新发布指向 `/api/taletv/v1` 的 TaleTV 包。

## 2. 备份并改数据库 schema

自托管 PostgreSQL 示例（`quickreels` 是示例用户名和数据库名，按 `.env.production` 调整）：

```bash
mkdir -p backups
sudo docker compose --env-file .env.production -f "$COMPOSE" exec -T postgres \
  pg_dump -U quickreels -d quickreels -Fc > "backups/before-taletv-rename-$(date +%Y%m%d-%H%M%S).dump"
sudo docker compose --env-file .env.production -f "$COMPOSE" exec -T postgres \
  psql -U quickreels -d quickreels -c \
  "SELECT schema_name FROM information_schema.schemata WHERE schema_name IN ('xu03', 'taletv');"
```

如果原 schema 是 `xu03` 且 `taletv` 尚不存在，原地重命名，**不要创建空 schema 代替原数据**：

```bash
sudo docker compose --env-file .env.production -f "$COMPOSE" exec -T postgres \
  psql -v ON_ERROR_STOP=1 -U quickreels -d quickreels \
  -c 'ALTER SCHEMA "xu03" RENAME TO "taletv";'
```

如果 TaleTV 原来使用独立数据库而不是 schema，不需要 `ALTER SCHEMA`，保留原数据库和全部数据，只需将新的 `TALETV_DATABASE_URL` 指向它。如果 `taletv` 已存在，先核对它是否承载现有数据，不要再次重命名。共享平台若使用 `SHARED_PLATFORM_DATABASE_URL` 指向另一数据库，还应单独备份该数据库。

## 3. 更新生产配置

编辑服务器的 `.env.production`（或 `QUICKREELS_ENV_FILE` 指定的文件）。把旧的 `XU03_` / `VITE_XU03_` 变量名改为 `TALETV_` / `VITE_TALETV_`，保持原有 TikTok Client Key、Client Secret、App ID 和 BytePlus 凭证值不变。重要项如下：

```env
DATABASE_URL=postgresql://USER:PASSWORD@HOST:5432/quickreels?schema=public
TALETV_DATABASE_URL=postgresql://USER:PASSWORD@HOST:5432/quickreels?schema=taletv
TALETV_TIKTOK_CLIENT_KEY=<TaleTV 原有 Client Key>
TALETV_TIKTOK_CLIENT_SECRET=<TaleTV 原有 Client Secret>
TALETV_TIKTOK_APP_ID=<TaleTV 原有 App ID>
REWARDED_PLACEMENT_ID=ad7686459794040702993
TALETV_REWARDED_PLACEMENT_ID=ad7688599028879722512
APP_ENTRY_PLACEMENT_ID=ad7686459458972829697
# 只有已有独立的 TaleTV 进入广告位时才设置：
# TALETV_APP_ENTRY_PLACEMENT_ID=<TaleTV 进入广告位 ID>
VITE_API_BASE_URL=https://api.evergreenprosper.com/api/v1
VITE_TALETV_API_BASE_URL=https://api.evergreenprosper.com/api/taletv/v1
VITE_TALETV_REWARDED_PLACEMENT_ID=ad7688599028879722512
```

`ad7688599028879722512` 在本项目中作为 TaleTV 的**剧集激励解锁**广告位，不要未确认广告类型就填进进入广告位。`SHARED_PLATFORM_DATABASE_URL` 若已使用则保持原值，不能指到新建空库。确认反向代理没有限制 `/api/taletv/v1`。

## 4. 构建与迁移

```bash
sudo docker compose --env-file .env.production -f "$COMPOSE" build api worker admin
sudo docker compose --env-file .env.production -f "$COMPOSE" run --rm --no-deps api \
  sh -lc './node_modules/.bin/prisma migrate deploy'
sudo docker compose --env-file .env.production -f "$COMPOSE" run --rm --no-deps api \
  sh -lc 'DATABASE_URL="$TALETV_DATABASE_URL" ./node_modules/.bin/prisma migrate deploy'
```

第二条迁移在已有数据的 TaleTV schema 上运行，不能省略。若共享平台表在独立的 `SHARED_PLATFORM_DATABASE_URL`，再执行：

```bash
sudo docker compose --env-file .env.production -f "$COMPOSE" run --rm --no-deps api \
  sh -lc 'DATABASE_URL="$SHARED_PLATFORM_DATABASE_URL" ./node_modules/.bin/prisma migrate deploy'
```

新增迁移会将共享媒资、授权、任务记录中的旧内部 key 转为 `taletv`，以及取消入口广告位的数据库级主小程序默认值。确认每条迁移成功后再启动服务。不要运行生产内容 seed。

## 5. 启动与验收

```bash
sudo docker compose --env-file .env.production -f "$COMPOSE" up -d api worker admin
sudo docker compose --env-file .env.production -f "$COMPOSE" ps
curl -fsS https://api.evergreenprosper.com/ready
curl -fsS https://api.evergreenprosper.com/api/taletv/v1/albums
curl -fsS https://api.evergreenprosper.com/api/v1/albums
sudo docker compose --env-file .env.production -f "$COMPOSE" logs --tail=100 api worker
```

管理后台刷新后选择 TaleTV，重新登录，确认独立剧集/广告配置仍在。旧 JWT 的 appKey 已失效，重新登录是正常的；后台本地草稿和模板会从旧 key 自动迁移。TaleTV 小程序升级后匿名访客标识会沿用，访问令牌会重新申请。

小程序发布包需在本机（有 TikTok Minis CLI 和真实 `apps/taletv/.env` 的环境）执行：

```bash
pnpm install --frozen-lockfile
pnpm --filter taletv build:minis:release
```

检查 `apps/taletv/minis.config.json` 的 App ID，以及 `apps/taletv/.env` 的 `VITE_API_BASE_URL=https://api.evergreenprosper.com/api/taletv/v1` 和 TaleTV Client Key。重新上传 TaleTV 包，验证实际剧集播放和激励广告。隐私政策和服务条款仍在 `/taletv/privacy`、`/taletv/terms`，参考 [Developer Portal 部署说明](taletv-portal-and-legal-deployment.md)。
