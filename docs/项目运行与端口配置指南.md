# QuicK ReeLS 项目运行与端口配置指南

本文说明如何在 Windows 本地启动 QuicK ReeLS 的用户端小程序 H5、运营管理后台、后端 API、PostgreSQL 和 BytePlus VOD 上传 Worker。

## 1. 项目组成

| 服务 | 目录 / 启动命令 | 默认地址 | 用途 |
| --- | --- | --- | --- |
| 用户端小程序 H5 | `pnpm dev:mini` | `http://localhost:5173` | 浏览短剧、观看、解锁和个人中心的浏览器预览版。 |
| 运营管理后台 | `pnpm dev:admin` | `http://localhost:5174` | 管理剧集、创建上传任务和配置页面模块。 |
| 后端 API | `pnpm dev:api` | `http://localhost:3000` | 为小程序、后台、数据和鉴权提供接口。健康检查：`http://localhost:3000/health`。 |
| PostgreSQL | `docker compose up -d postgres` | `localhost:5432` | 本地业务数据、管理员、剧集和上传任务。 |
| BytePlus 上传 Worker | `pnpm dev:worker` | 无网页端口 | 每 30 秒处理一次待上传任务，将公网视频 URL 提交给 BytePlus VOD。 |

这五项是独立进程。关闭其中某个 PowerShell 窗口，只会停止对应服务。

## 2. 第一次启动前的准备

### 必需软件

- Node.js（项目当前使用 Node 24）。
- pnpm 11.19.0：运行 `pnpm --version` 应显示 `11.19.0`。
- Docker Desktop：用于启动 PostgreSQL。

### 安装依赖

在项目根目录执行：

```powershell
cd "D:\my project\tiktok-project"
pnpm install
```

### 配置后端环境变量

若尚未创建，复制模板：

```powershell
Copy-Item apps\api\.env.example apps\api\.env
```

编辑 `apps/api/.env`，至少确认以下内容：

```env
PORT=3000
DATABASE_URL=postgresql://quickreels:change-this-local-password@localhost:5432/quickreels?schema=public
API_CORS_ORIGIN=http://localhost:5173,http://localhost:5174
JWT_SECRET=替换为至少32个字符的随机字符串

ADMIN_BOOTSTRAP_EMAIL=你的管理员邮箱
ADMIN_BOOTSTRAP_PASSWORD=至少12位的强密码

BYTEPLUS_ACCOUNT_ID=你的BytePlus账户ID
BYTEPLUS_SPACE_NAME=你的VOD空间名称
BYTEPLUS_REGION=ap-southeast-1
BYTEPLUS_ACCESS_KEY=你的AccessKey
BYTEPLUS_SECRET_KEY=你的SecretKey
BYTEPLUS_VOD_ENDPOINT=https://vod.byteplusapi.com
```

不要把 `.env`、BytePlus Access Key、Secret Key、TikTok Client Secret 或后台密码提交到 Git 仓库、上传网盘或发送到聊天中。

`ADMIN_BOOTSTRAP_EMAIL` 和 `ADMIN_BOOTSTRAP_PASSWORD` 只在运行 `pnpm db:seed` 时用于创建第一个后台账号；两项必须同时存在，密码至少 12 位。

## 3. 首次初始化数据库

先启动 PostgreSQL：

```powershell
docker compose up -d postgres
```

确认容器已运行：

```powershell
docker compose ps
```

再在项目根目录执行：

```powershell
pnpm db:generate
pnpm db:migrate
pnpm db:seed
```

命令含义：

- `db:generate`：生成 Prisma 数据库客户端。
- `db:migrate`：将项目中的数据库迁移应用到本地 PostgreSQL。
- `db:seed`：写入演示剧集、页面组件、分类，以及 `.env` 中配置的第一个后台管理员。

`pnpm db:seed` 成功后直接退出是正常行为；它不会启动任何网页服务。

## 4. 日常启动方式

打开四个 PowerShell 窗口，每个窗口都先进入项目根目录：

```powershell
cd "D:\my project\tiktok-project"
```

第 1 个窗口启动 API：

```powershell
pnpm dev:api
```

启动成功后访问：`http://localhost:3000/health`，应返回 HTTP `200`。

第 2 个窗口启动用户端小程序 H5：

```powershell
pnpm dev:mini
```

在浏览器访问：`http://localhost:5173`。

第 3 个窗口启动运营管理后台：

```powershell
pnpm dev:admin
```

在浏览器访问：`http://localhost:5174`，使用 `apps/api/.env` 中的 `ADMIN_BOOTSTRAP_EMAIL` 和 `ADMIN_BOOTSTRAP_PASSWORD` 登录。

第 4 个窗口启动 BytePlus 上传 Worker：

```powershell
pnpm dev:worker
```

Worker 没有浏览器页面。它运行后会持续轮询数据库中待处理的上传任务，默认间隔为 30 秒。

数据库容器不需要每天重新创建；若 Docker Desktop 已启动，只需确认它在运行：

```powershell
docker compose up -d postgres
```

## 5. 小程序 H5 预览与真实 API

用户端 `apps/mini-web` 默认使用演示数据，因此即使 API 未启动，也可以预览首页、详情、激励解锁、播放和个人中心流程。这是浏览器预览模式，不代表已连接真实数据库或 TikTok 平台。

如需让用户端连接本地 API，在 `apps/mini-web/.env` 中设置：

```env
VITE_API_BASE_URL=http://localhost:3000/api/v1
VITE_DEMO_MODE=false
VITE_USE_MOCK_API=false
VITE_ENABLE_MOCK_FALLBACK=false
```

修改前端 `.env` 后，需要停止并重新执行 `pnpm dev:mini`。

在 TikTok Mini 的真实预览或发布环境里，TikTok 登录、激励广告和原生播放能力需要由 TikTok 平台配置；浏览器中的 H5 页面只展示可安全预览的替代行为。

## 6. 端口在哪里配置

| 服务 | 当前端口 | 配置文件 | 修改方式 |
| --- | ---: | --- | --- |
| 用户端小程序 H5 | `5173` | `apps/mini-web/vite.config.ts` 的 `server.port` | 修改数字后重启 `pnpm dev:mini`。 |
| 运营管理后台 | `5174` | `apps/admin-web/vite.config.ts` 的 `server.port` | 修改数字后重启 `pnpm dev:admin`。 |
| 后端 API | `3000` | `apps/api/.env` 的 `PORT` | 修改后重启 `pnpm dev:api`。 |
| PostgreSQL 主机映射 | `5432` | `docker-compose.yml` 的 `ports: "5432:5432"` | 修改左侧端口，同时修改 `DATABASE_URL`。 |
| Worker 轮询间隔 | `30000` ms | `apps/api/.env` 的 `UPLOAD_WORKER_INTERVAL_MS` | 修改后重启 `pnpm dev:worker`。 |

若修改了用户端或后台端口，必须同步更新 API 的跨域白名单。例如改为 `5175` 和 `5176` 时：

```env
API_CORS_ORIGIN=http://localhost:5175,http://localhost:5176
```

若修改 API 端口，例如改为 `3100`，还需要同步修改两个前端的 API 地址：

```env
VITE_API_BASE_URL=http://localhost:3100/api/v1
```

用户端使用 `apps/mini-web/.env`；管理后台可在 `apps/admin-web/.env` 中设置同名变量。未设置时，两个前端默认访问 `http://localhost:3000/api/v1`。

## 7. BytePlus VOD 上传操作

1. 启动 API、管理后台和 Worker。
2. 访问 `http://localhost:5174` 并登录。
3. 打开“上传任务”。
4. 输入本地集 ID，例如种子数据的 `demo-episode-1`。
5. 填写能被公网直接访问的 `.mp4` 视频 URL；不能是需要登录、短时即失效或只在本机可访问的地址。
6. 创建任务后，Worker 会调用 BytePlus VOD 异步导入并回写视频 VID 与时长。

BytePlus 的账户、空间、凭据、签名和项目上传链路细节请参考 [BytePlus VOD 项目手册](byteplus-vod-project-manual.md)。

## 8. 常见问题

### `pnpm` 找不到或被 PowerShell 拦截

确认：

```powershell
pnpm --version
```

应输出 `11.19.0`。若旧 PowerShell 窗口仍保存了过期命令解析，关闭该窗口并重新打开。也可以临时使用：

```powershell
pnpm.cmd db:seed
```

### `http://localhost:5173` 或 `http://localhost:5174` 打不开

对应页面没有启动。分别在独立窗口执行：

```powershell
pnpm dev:mini
pnpm dev:admin
```

若 Vite 提示端口被占用，可检查占用进程：

```powershell
Get-NetTCPConnection -State Listen -LocalPort 5173,5174 | Select-Object LocalPort,OwningProcess
```

### 后台无法登录

检查 `apps/api/.env` 中管理员邮箱和密码都存在，且密码不少于 12 位。然后执行：

```powershell
pnpm db:seed
```

管理员已存在时，seed 不会覆盖已有密码。若需要更换密码，应使用后台用户管理流程或直接在数据库中安全地更新密码哈希，不要期望再次 seed 自动改密码。

### API 无法连接数据库

依次检查：

```powershell
docker compose ps
docker compose up -d postgres
pnpm db:migrate
```

确认 `apps/api/.env` 的 `DATABASE_URL` 与 `docker-compose.yml` 的数据库名、用户名、密码和端口一致。

### BytePlus 上传任务一直没有完成

确认 `pnpm dev:worker` 正在运行，并检查 `apps/api/.env` 中的 `BYTEPLUS_ACCOUNT_ID`、`BYTEPLUS_SPACE_NAME`、`BYTEPLUS_REGION`、`BYTEPLUS_ACCESS_KEY` 和 `BYTEPLUS_SECRET_KEY`。视频 URL 必须可被 BytePlus 从公网读取。

## 9. 停止服务

- 在 API、Mini、Admin、Worker 对应的 PowerShell 窗口按 `Ctrl+C`，停止对应 Node 服务。
- 停止 PostgreSQL 容器：

```powershell
docker compose stop postgres
```

这不会删除数据库数据。只有执行 `docker compose down -v` 才会删除本项目的 Docker 卷和本地数据库数据；不要在需要保留数据时执行它。
