# 广告预加载与投放策略更新记录（2026-10-27）

## 更新范围

本次更新集中在 TikTok Minis 广告链路：前端广告实例预加载和入口广告衔接、API 侧的展示计数与插屏策略、数据库策略字段、管理后台控制项，以及相关测试。没有修改生产服务器，也没有应用生产数据库迁移。

## 小程序前端

- 新增广告实例预加载池。每个广告位最多保留两个实例，分别用于当前展示和下一次展示；运行时支持 `load()` 时，在展示前启动加载，并等待 `onLoad`。加载最多等待 8 秒，超时或加载失败会进入现有错误处理，清理事件监听和实例。
- 入口会话返回广告位后立即预热广告；入口广告展示期间也准备下一条广告。广告关闭后，下一条尽快调用 SDK，避免把数据库确认网络往返放在相邻广告的展示之间。
- `SHOWN` 计数模式会在 SDK 接受展示时推进本地计数，并把服务器确认按广告序号排队。确认请求遇到网络错误、服务端错误或 429 时最多重试 3 次；重试使用同一个事件 ID 和序号。只有最后一条展示确认成功后入口门禁才放行，持续失败则拒绝放行。这样广告之间不等待 API，但不会因为短暂断网丢掉服务器计数。
- `COMPLETED` 模式保持原有奖励校验：需要完整观看并调用完成接口后才计入入口门禁进度。两种计数模式由服务器策略决定。
- 广告错误归一化增加 TikTok 字段 `error_code`、`error_msg`、`sub_error_code`、`error_extra` 的提取，并将广告事件错误信息长度上限提高到 500 字符，便于从后台诊断真实 SDK 错误。
- 剧集解锁激励广告仍会提前准备广告实例。
- 剧集插屏增加首次等待时间、后续间隔、最短间隔、每会话次数上限、初始跳过集数、之后每 N 次切集触发一次、激励广告后冷却等规则。页面还会按服务端配置启动定时插屏调度，并在页面离开或隐藏时停止调度。
- 插屏配置请求现在带上当前 `VITE_MINI_RELEASE_ID`，并将版本号加入查询缓存键，避免多个发布版本共用 `default` 策略。未设置版本号的旧包继续使用 `default` 策略。

## 后端 API

- 新增 `POST /app-entry-ad-sessions/:sessionId/shown`，供 `SHOWN` 模式确认一次广告展示。接口检查用户与会话归属、计数模式、广告序号、事件 ID 和展示顺序；重复的相同确认可幂等返回，冲突序号会返回冲突错误。
- 展示事件写入、会话计数推进和状态更新放在 Serializable 事务中；遇到 PostgreSQL 序列化冲突时进行有限重试，减少并发确认造成的重复计数或请求失败。
- `COMPLETED` 模式原有 `/complete` 完播验证保留，没有改成只按弹出计数。
- `/episode-interstitial/config` 返回是否启用、广告位和全部调度参数，并根据 `releaseId` 读取对应策略；无广告位时仍返回禁用状态。
- `SHOWN` 模式下，已经计入展示的广告即使随后不完整关闭，也允许继续上报该次 `CLOSED_INCOMPLETE` 事件，避免展示计数完成后会话关闭导致事件被拒绝。
- 管理策略输入增加数值边界校验：延迟/间隔范围最高 86400 秒，会话次数最多 20，切集频率最多 100。

## 数据库

`AppEntryAdPolicy` 增加 8 个剧集插屏策略字段：启用状态、首次延迟、重复间隔、最短间隔、会话上限、初始跳过切集数、后续切集频率、激励广告冷却时间。Prisma schema 和迁移文件已加入版本控制。迁移只新增带默认值的列，不删除既有数据；执行生产发布前仍须先运行迁移，再更新依赖新字段的 API。

## 管理后台

入口广告策略页增加“剧集切换插屏调度”配置区域，可按构建包标识调整启用状态、首次延迟、后续间隔、最短间隔、会话上限、初始跳过次数、后续触发频率和激励广告冷却时间。保存仍走既有广告策略 API 和版本级策略存储。

## Minis 本地调试配置

StoryFlicks 的 `minis.config.json` 增加公开的 `dev.clientKey`，便于本地 Minis CLI 识别开发小程序。删除了 CLI 注入到 `index.html` 的调试元数据；其中包含虚拟网卡地址 `172.17.96.1:5193`，不应进入构建产物或提交后的静态入口页。该 `clientKey` 是应用标识，不是客户端密钥；没有提交服务器密码或其他私密配置。

## 发布顺序与兼容性

1. 备份并对目标数据库执行 Prisma 迁移（部署环境使用 `prisma migrate deploy`）。
2. 更新 API 镜像并检查 `/ready`、新策略读取和入口展示确认接口。
3. 更新管理后台，使新增策略项可以配置。
4. 再构建和发布使用 `SHOWN` 模式或按发布版本读取插屏策略的新小程序包。

数据库字段为增量新增；更新后的 API 保留旧 `/complete` 行为，并继续接受未携带 `releaseId` 的旧包请求。旧包的插屏策略因此使用 `default` 记录。新包要使用独立版本策略，构建时必须设置稳定的 `VITE_MINI_RELEASE_ID`，并在后台为该标识配置策略。新小程序包依赖新的 `/shown` API，因此不能先于 API 更新发布。

本次只完成本地提交准备，不代表生产服务器已更新；生产迁移、镜像更新和线上健康检查仍需单独部署执行。
