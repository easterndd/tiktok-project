# 激励广告与短剧播放器优化方案

## 1. 目标与结论

本方案只保留“看完激励视频后解锁剧集”的商业化能力；插屏广告暂时完全暂停；短剧播放器从当前的“单集初始化即可播放”优化为官方推荐的“单播放器实例、连续切集、预加载、可观测”的播放链路。

当前激励广告主链路可继续使用：前端调用 `TTMinis.createRewardedVideoAd`，仅在 `onClose({ isEnded: true })` 后请求后端完成解锁；后端要求对应的 `SHOWN` 广告事件存在，才创建奖励记录和解锁剧集。这符合官方指南的核心要求。

当前短剧播放器也能作为基础播放版本使用：通过 `TTMinis.getPlayer('byteplus')` 创建播放器，传入 `vid`、`albumId`、`episodeId` 和可选 `playAuthToken`，且没有直接引入 `@byteplus/veplayer`。但它尚未采用官方建议的单实例连续播放和预加载策略，首帧埋点也不准确，应优先优化后再做真机验收。

## 2. 范围与非范围

| 范围 | 决策 |
| --- | --- |
| 激励视频广告 | 保留，继续用于付费剧集的广告解锁。 |
| 插屏广告 | 暂停，不在小程序启动、进集或播放中展示。 |
| 短剧播放器 | 按 TikTok Minis / VePlayer 官方建议重构播放生命周期、切集与预加载。 |
| 后端剧集鉴权 | 保留现有 `/episodes/:episodeId/play` 和奖励会话校验，不改变权益规则。 |
| 广告后台能力 | 保留数据表和管理能力，但关闭入口广告策略，方便以后有合规场景时恢复。 |

## 3. 插屏广告暂停方案

### 3.1 原因

官方插屏广告指南不建议把插屏广告作为打开 Minis、打开剧集或频繁重复动作的触发条件。项目当前把 `EntryAdGate` 包在全局 `AppProviders` 外层，应用启动时可能要求用户先完成插屏或激励广告才能进入内容；这不符合当前没有明确插屏场景的产品状态，也会增加审核和留存风险。

### 3.2 实施内容

1. 前端移除全局入口门禁。
   - 在 `apps/mini-web/src/app/providers.tsx` 移除 `EntryAdGate` 对应用内容的包裹。
   - `apps/mini-web/src/components/EntryAdGate.tsx` 和 `apps/mini-web/src/features/ads/app-entry-ad.ts` 暂不删除，保留为未来功能代码；但不再由正常启动流程调用。

2. 后端关闭入口广告策略。
   - 将后台默认值和生产环境当前生效配置设为 `enabled = false`。
   - 不创建新的入口广告会话，不让管理端配置意外恢复后阻断用户进入小程序。

3. 保留审计数据，不迁移或删除已有广告事件、入口会话和配置表。

### 3.3 后续恢复插屏的准入条件

只有出现明确且不打断核心操作的节点时才恢复，例如完成一章的自然结算页、用户主动返回发现页后的过渡页。恢复时应满足：

- 使用 `TTMinis.canIUse('createInterstitialAd')` 能力检测。
- 每次展示创建新的 `createInterstitialAd({ adUnitId })` 实例。
- 设置业务层频次控制，例如同一用户完成 N 个章节后至多展示一次，并设置冷却时间。
- `onClose` 后无条件继续业务流程；展示失败也不能阻塞用户。
- 不把插屏广告视为奖励，也不要求用户完成观看。

## 4. 激励视频广告保留与加固

### 4.1 现有链路

```text
用户点击“看广告解锁”
  -> 创建奖励会话
  -> canIUse('createRewardedVideoAd')
  -> 创建当次广告实例并 show()
  -> onClose(isEnded === true)
  -> 上报 SHOWN 事件并请求奖励完成接口
  -> 后端校验 SHOWN 事件、创建奖励记录、解锁剧集
```

该流程继续保持，特别是“未完整看完不发奖”和“每次展示新建广告实例”两项不能退化。

### 4.2 小幅加固项

| 项目 | 处理方式 | 原因 |
| --- | --- | --- |
| 展示事件时序 | 将 `SHOWN` 事件的确认与 `onClose` 的完成逻辑做成明确状态机，避免极端情况下关闭回调先于 `show()` Promise 写入状态。 | 现有逻辑对该时序较敏感。 |
| 唯一事件 ID | 延续现有 `crypto.randomUUID()` 降级方案，所有广告事件使用同一轮展示的关联 ID。 | 支持后端幂等校验与排障。 |
| 错误体验 | 广告不可用、加载失败或用户未看完时，保持剧集锁定并返回可理解的提示；不得将播放页卡死。 | 官方建议广告失败不影响主应用稳定性。 |
| 监控 | 按广告位、剧集、失败码、完成率统计 `REQUESTED`、`SHOWN`、`CLOSED_INCOMPLETE`、`FAILED`。 | 用于发现填充率或版本兼容问题。 |

## 5. 短剧播放器重构方案

### 5.1 当前问题

- `PlayerShell` 在 `playInfo` 变化后销毁并重建播放器，连续追剧时会反复初始化。
- 首帧事件在播放器构造 Promise 返回时即上报，而非播放器官方的 `VePlayer.Events.LOAD_START`，启动耗时数据不可信。
- 事件名称以字符串直接订阅，类型声明没有暴露 `VePlayer.Events`，无法与 SDK 的实际事件常量对齐。
- 没有 `playNext()`、`prefetchMediaInfo()`、`prepare()`、`setPreloadList()` 或媒体信息缓存策略，下一集切换无法利用官方能力。
- 页面可见性变化时只上报进度，没有形成完整的 WebView 生命周期恢复策略。

### 5.2 目标架构

```text
WatchPage
  -> PlayerShell（负责 UI、进度上报、错误展示）
     -> DramaPlayerController（单例播放器生命周期）
        -> TTMinis.getPlayer('byteplus')（构造器缓存）
        -> VePlayer 实例（同专辑连续播放）
        -> 播放信息缓存 / 相邻集预取 / 预加载队列
  -> API：获取当前集和相邻集的 vid、albumId、episodeId、token
```

核心原则：一个播放页仅维护一个 VePlayer 实例。同一专辑切换下一集时优先用 `playNext()`，不重新创建播放器；离开播放页、切换专辑或组件卸载时才 `destroy()`。

### 5.3 前端改造清单

1. 扩展 TikTok SDK 类型。
   - 文件：`apps/mini-web/src/types/ttminis.d.ts`。
   - 补充 `VePlayer.Events`、`playNext`、`prefetchMediaInfo`、`prepare`、`setPreloadList` / `addPreloadList` 等本次实际使用的 API 类型。
   - 类型以官方 SDK 文档当前字段为准；不自行引入 `@byteplus/veplayer` 包。

2. 缓存播放器构造器。
   - 文件：`apps/mini-web/src/features/player/create-player.ts`。
   - `TTMinis.getPlayer('byteplus')` 在 `TTMinis.init()` 成功后只获取一次并缓存构造器。
   - 创建播放器时继续传入 `root`、`vid`、`albumId`、`episodeId`；仅在实际需要时带上 `playAuthToken`。

3. 引入 `DramaPlayerController`。
   - 新增位置建议：`apps/mini-web/src/features/player/drama-player-controller.ts`。
   - 职责：创建/销毁单例、订阅和解绑官方事件、`playNext` 切集、暴露当前剧集状态、管理预加载队列。
   - 组件不直接持有 SDK 细节，避免 React 重渲染导致实例反复销毁。

4. 重写 `PlayerShell` 生命周期。
   - 文件：`apps/mini-web/src/components/PlayerShell.tsx`。
   - 首帧指标改为监听 `VePlayer.Events.LOAD_START` 后记录，并单独记录初始化开始时间、首帧时间、错误码和结束事件。
   - 使用 SDK 官方事件常量订阅 `TIME_UPDATE`、`PAUSE`、`ENDED`、`ERROR` 等事件；实际事件名以 SDK 类型和真机日志确认。
   - 页面隐藏时保存进度；页面恢复时校验播放器状态并恢复必要的事件和播放状态。
   - 组件卸载时先解绑监听再 `destroy()`，避免旧实例继续上报进度。

5. 加入相邻集预取和预加载。
   - 在发现页或剧集列表曝光时，对用户最可能点击的剧集调用 `VePlayer.prefetchMediaInfo()`，参数必须使用 `albumId`、`episodeId`、`vid`，不能传直接视频 URL。
   - 进入播放页后，将当前集后一集作为最低配预加载目标；网络和内存允许时再加入前一集。
   - 用 `prepare()` / `setPreloadList()` 建立有序队列，顺序与当前剧集列表一致。
   - 预加载必须设置数量和内存上限；切换专辑、退出播放页或网络异常时清空过期队列。

6. 使用连续播放切集。
   - `WatchPage` 获取当前集的相邻剧集播放信息，或由新增的轻量批量播放信息接口返回。
   - 同专辑下一集触发时，将目标剧集交给控制器的 `playNext()`；页面路由、标题、当前集状态同步更新。
   - 发生 `playNext()` 错误时，降级为销毁后重建一次播放器，并上报 `EPISODE_SWITCH_FAILED`；失败不应循环重试。

### 5.4 后端配合

现有 `/episodes/:episodeId/play` 已返回播放器需要的主字段。为支持可靠的相邻集预加载，建议新增只面向已授权剧集的批量播放信息接口，或在当前专辑详情响应中附带受限的播放器标识信息：

- 必填：`albumId`、`episodeId`、`vid`。
- 可选：`playAuthToken`，按需生成，避免为大量未播放剧集提前申请令牌。
- 鉴权：只返回用户已经解锁、免费或当前业务允许预加载的剧集；不能因为预加载绕过单集权益。
- 缓存：缓存不含令牌的媒体标识；令牌按短时效和服务商要求生成。

如果服务商要求每个预加载剧集都必须带有效 token，接口应采用“当前集 + 下一集”小批量按需返回，而不是一次性签发全专辑 token。

## 6. 推荐实施顺序

### 阶段 A：先消除入口广告影响

1. 前端停止挂载 `EntryAdGate`。
2. 生产与默认入口广告配置统一关闭。
3. 回归验证：首次进入、匿名会话、登录后进入都不再触发插屏或入口激励广告。

### 阶段 B：播放器基础稳定性

1. 完成 SDK 类型补齐和构造器缓存。
2. 引入 `DramaPlayerController`，实现单实例创建、销毁、标准事件订阅与错误处理。
3. 修正首帧、播放结束、错误和进度埋点。
4. 回归验证单集播放、切换路由、返回列表、前后台切换、错误降级。

### 阶段 C：连续播放体验

1. 补齐相邻剧集播放信息获取。
2. 接入 `playNext()` 与路由状态同步。
3. 接入下一集媒体信息预取及有限预加载。
4. 在弱网、无 MSE/MMS 支持和 token 获取失败时验证降级路径。

### 阶段 D：真机发布验收

1. 在 TikTok Minis Debug 模式和真实 TikTok 客户端测试；PC 调试环境不能作为真实播放信息的最终依据。
2. 检查 TikTok App 版本和 `canIUse` 能力分支。
3. 用已审核、可播放的短剧内容验证播放器；重点记录官方错误码、首帧耗时、切集成功率和预加载命中率。
4. 验证激励广告：完整观看解锁、提前关闭不解锁、加载失败不解锁、多次广告解锁、重复请求幂等。

## 7. 验收标准

| 能力 | 通过标准 |
| --- | --- |
| 插屏暂停 | 冷启动、热启动、进入剧集和播放中均不调用 `createInterstitialAd`，入口广告配置关闭。 |
| 激励解锁 | 仅 `isEnded === true` 后解锁；未完整观看、广告失败和重复完成请求均不会错误发放权益。 |
| 基础播放 | 已审核剧集在 TikTok Minis 真机环境中可加载、播放、暂停、结束和恢复。 |
| 连续播放 | 同专辑下一集优先通过 `playNext()` 切换，失败时只做一次受控降级重建。 |
| 预加载 | 不传直接 URL；相邻集预加载不突破权益；异常时不影响当前集播放。 |
| 可观测性
| 首帧、结束、错误、切集失败、预加载命中和广告漏斗均能关联到剧集、会话与客户端版本。 |

## 8. 风险与控制

- TikTok SDK 的可用 API 与事件常量受客户端版本影响：所有新能力必须经 `canIUse` 或实际 SDK 能力检测后启用，并提供单集重建播放的降级路径。
- `playAuthToken` 的时效和预加载策略相互约束：不能把 token 当作长期缓存数据；由后端按需要签发。
- 预加载会增加带宽和内存：默认只加载下一集，按设备和网络质量逐步放大，不应一进剧集页就预加载整部剧。
- 当前前端播放器和入口广告模块没有覆盖测试：改造后至少添加控制器单元测试，以及广告和切集关键状态的集成测试。

## 10. 不应做的事情

- 不重新引入或安装 `@byteplus/veplayer`。
- 不用原生 HTML `<video>` 或第三方播放器替换 TikTok Minis 短剧播放器。
- 不用插屏广告作为启动应用、打开剧集或关键操作的前置门槛。
- 不在 `isEnded` 为 `false` 时解锁任何剧集。
- 不复用同一个广告实例展示多次。
- 不在预加载请求中传入视频直链，也不批量长期缓存播放授权 token。
