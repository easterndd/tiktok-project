# 剧目统一展示资料同步

剧目列表的“编辑剧名与简介”、快捷改名，以及“剧目素材”的文案保存，都使用统一展示资料。识别同一部剧依赖现有共享剧目及小程序授权映射，不按剧名匹配。

## 使用

1. 登录主小程序 OWNER，打开剧目编辑窗口。关联应用的 OWNER 如果同时拥有主小程序 OWNER 权限，也可以编辑；不同账号可先在同一标签页登录主应用再切回。
2. 窗口显示全部关联应用，包括主应用，以及已有资料的差异。首次默认读取主应用的当前展示文案，确认范围后保存。
3. 保存同时提交剧名、简介和全部多语言标题/简介，生成递增的统一资料版本。同步是异步处理，窗口每 3 秒刷新任务结果；关闭窗口不影响任务。
4. 各应用分别显示等待、处理中、成功或失败。临时故障自动重试，修复配置或映射后也可以点击单应用“重试”。播放授权状态独立于资料同步状态。

保留各应用的基础封面、语言封面、广告位、收费配置和播放映射。未包含在统一语言列表中的目标专有语言，其标题/简介改用统一基础文案，保留该语言封面，避免旧语言文案继续覆盖新的统一资料。系统不会自动翻译文案。

原本与基础剧名或简介完全一致、且本次没有单独修改的语言字段，会跟随基础文案更新；单独编写的翻译保留。没有统一文案编辑权限的管理员仍可在素材页维护当前应用封面。新语言的封面保存不需要等待异步文案同步完成。

新授权副本继承已经建立的统一资料。此前在没有共享关系时显式保存的展示文案，也会在首次授权时初始化为统一资料。普通 TikTok 授权对账不会重置统一文案。TikTok 平台审核、版本及上下架仍按原流程操作。

没有共享关系的独立剧目只更新当前应用。已撤销授权的应用不参与同步；缺失目标映射会显示失败，修复后重试。各应用独立上传且没有共享关系的同名剧目，需要先确定共享归属和映射。

## 启用

本次数据库迁移为 `20261010090000_shared_display_metadata`。先对所有已配置的小程序数据库/schema以及独立共享库执行既有迁移流程，再启用新 API 和 worker；只迁移主应用会导致其他应用同步失败。

使用 `apps/api` 的运行环境，在该目录执行：

```powershell
pnpm exec prisma migrate deploy
```

每次通过 `DATABASE_URL` 指向对应的小程序数据库/schema。`SHARED_PLATFORM_DATABASE_URL` 如果单独配置，也需要执行迁移。数据库地址来自部署环境配置，不要写入源码或文档。随后重启 API、后台前端和现有上传/共享任务 worker，无需重新发布小程序。

本地实施时 `localhost:5432` 没有 PostgreSQL 监听，因此本地迁移未能执行；迁移文件、Prisma Client 和应用代码已准备。正式环境尚未部署。
