```text

CLOSED_COMPLETED    广告完整结束
```

因此后台“广告尝试异常”不等于用户关闭广告未获得奖励。

## 2026-10-23：入口广告与共享 IP 解耦

提交：`18b92ee`

这是本阶段最后一次更新，只修改 API。

此前入口广告请求可能依次等待：

```text
共享 IP 记录写入
入口广告策略查询
IP 豁免查询
用户豁免查询
```

现在改为：

- 共享 IP 访问记录进入异步队列。
- 入口策略不再等待共享 IP 写入完成。
- 共享 IP 队列最多 256 条。
- 共享 IP 查询失败时记录日志，但入口广告继续判断。
- IP 记录失败不会直接导致入口广告接口返回 500。

主要文件：

- `apps/api/src/modules/app-entry-ads/routes.ts`
- `apps/api/src/services/shared-ip.service.ts`

该提交针对此前出现的 `POST /app-entry-ad-sessions HTTP 500`、`ENTRY_AD_POLICY` 和 `ENTRY_GATE_SLOW` 等问题进行服务器侧隔离。

## 当前小程序启动流程

```text
HTML 启动画面
  ↓
TikTok Mini SDK
  ↓
匿名会话
  ↓
入口广告策略
  ↓
入口广告展示/完成
  ↓
EntryAdGate READY
  ↓
首页接口
  ↓
首页缓存或首页数据
```

如果入口策略配置为激励广告门槛，首页变慢可能来自：

- TikTok 原生广告填充和展示。
- 用户没有完整看完广告。
- 广告展示失败后的自动重试。
- WebView 到 API 的网络。
- 入口策略本身要求多次完成广告。

API 服务端查询耗时只是整个等待过程的一部分。

## 当前限制

当前生产版本包含上述 Git 代码，但以下因素仍由 TikTok 原生广告 SDK 和客户端运行环境决定：

- 广告是否有填充。
- 原生广告是否及时返回。
- WebView 是否及时加载。
- 用户是否完整观看广告。

API 可以记录和处理这些结果，但不能直接控制广告平台的填充速度。
