# 内容创建、追加分集与版本发布需求

> 状态：已实现主要流程，真实 TikTok 平台端到端验收仍需在已配置环境执行。
> 范围：运营后台、管理 API、平台同步任务、公开剧集接口。

## 1. 目标

运营人员可以在已有剧集中追加分集，也可以创建新剧集。追加时沿用已有剧集的访问策略；此前已上线的分集继续可播放，新分集通过新版本审核并切换线上版本后才对观众可见。内容创建表单支持保存可复用模板，以及显式重置并开始新内容。

## 2. 改造前现状

- 内容创建页没有“新建 / 追加到已有剧集”的选择。未关联已保存分集时，提交会调用 `POST /admin/dramas` 创建新剧集；同名不会自动合并。
- 表单只有浏览器本地自动草稿，未提供独立模板和可见的重置按钮。创建成功后会清空表单；本地文件无法随草稿恢复。
- 已保存部分分集后，再在表单内添加新行，当前提交仅处理已有分集的视频上传，不会将新行写入原剧集。
- 已登记成功的 TikTok 视频会跳过重复登记；但同步版本会提交剧集全部分集的完整快照。审核对象是剧集版本。
- 审核状态与公开分集状态尚未充分按版本区分；新旧版本并存时有旧集下线或新集提前可见的风险。

## 3. 内容创建模式

### 3.1 新建剧集

1. 显示明确的“新建剧集”模式，提交后创建新剧集、访问策略和初始分集。
2. 创建前校验剧名、封面、集号、排序、视频和访问策略。剧名相同不代表同一剧集，不能隐式合并。
3. 成功创建与视频上传失败分别反馈；失败后仍可针对已创建分集重试，不可因此再次创建同名剧集。

### 3.2 追加到已有剧集

1. 先按剧集 ID 选择目标剧集，并显示剧名、现有集号范围、已上线集数、访问策略、线上版本和待审版本；确认目标后再编辑新增分集。
2. 默认从现有最大集号的下一集生成集号及默认标题；允许修改起始集号，后续行连续递增。保留手写标题。
3. 仅创建新增分集，拒绝与目标剧集已有集号重复；不得改写已有分集或把新行误关联到另一剧集。批量视频按实际集号匹配。
4. 新分集继承目标剧集的访问策略，不新建剧集或策略。追加界面如需调整策略，应显示为单独的剧集级修改并明确保存。
5. 新增分集在平台审核及发布完成前保持草稿状态，不得出现在公开分集列表或播放接口中。

## 4. 草稿、模板与重置

1. 自动草稿记录当前编辑会话及目标剧集 ID；恢复时明确显示“新建”或“追加”模式，避免误提交到另一部剧。
2. “保存为模板”独立于自动草稿，允许命名、查看、应用和删除。模板建议保存剧目类型、标签、广告位和解锁参数等可复用配置；剧名、简介、封面、视频文件、已保存分集 ID、上传任务和平台版本不得直接继承为新剧集数据。
3. “重置 / 新建”按钮清空当前编辑会话并回到新建模式，不删除已创建剧集或保存的模板。存在未保存输入或待重试上传时，先提示将丢失的内容。
4. 应用模板后，运营人员仍可逐项修改；模板修改不会回写已创建剧集的访问策略。

## 5. 追加分集后的 TikTok 发布流程

1. 新分集先完成 BytePlus 上传及 TikTok 视频登记。已就绪的旧分集不重新上传或登记；失败或状态未知的任务需有明确的重试、对账入口。
2. “同步版本”基于同一平台剧集 ID 创建新版本。请求包含旧分集及新分集的完整列表；旧分集复用平台分集 ID，新分集取得新的平台分集 ID。旧线上版本保持不变。
3. 送审针对**新剧集版本**，不对已审核通过的旧版本重复送审。界面须同时展示“当前线上版本”和“新版本待审状态”，并防止同一版本重复入队。
4. 新版审核通过后才允许设为线上版本；线上版本切换成功并对账确认后，新增分集才可公开。旧集在等待、驳回或失败期间持续按原线上版本播放。
5. 审核驳回时展示平台原因，允许修正后再生成版本；不得把旧版的通过状态用于新版。对账只更新对应版本的审核结果，不能把整部剧所有分集统一标为上线或下线。
6. 发布步骤出现超时或未知结果时先查询平台状态，避免重复创建版本、重复送审或错误切换线上版本。

## 6. 访问策略与集号

- 免费集数、广告解锁开关、广告位 ID 和每集所需观看次数属于剧集级配置；追加分集时沿用现有值。
- 分集级 `isFree` 仍需明确显示。当前服务端同时按 `isFree` 和 `episodeNo <= freeEpisodeCount` 判断免费，若从第 4 集开始创建且“免费集数”为 1，实际免费规则与“前 1 个录入分集”不同。实施前需明确“免费集数”按真实集号还是按该剧集排序后的前 N 集计算，并在界面和 API 中统一。
- 删除或修改尚未发布的新分集不应影响旧线上版本；集号冲突、跳号和排序变化应在提交前提示。

## 7. 运营界面与状态

- 最近平台任务表的“剧目 / 分集、操作、任务状态、时间 / 错误”各列在宽屏和窄屏横向滚动时保持对齐。长剧名截断并可查看完整名称；失败状态及错误文本同时可辨认。
- 每条平台任务应显示所针对的剧集及版本，区分“已入队、处理中、已完成、失败、结果未知”。剧集行显示当前线上版本和待发布版本，不以单一剧集状态代替版本状态。
- 按钮应根据实际版本状态启用；异步任务入队不等于平台操作成功。

## 8. 验收场景

1. 已有第 1–3 集在线，追加第 4 集后，访问策略仍为原剧集配置，旧集仍可播放；第 4 集审核前不可见。
2. 同步媒资只为第 4 集创建必要的视频任务；同步版本包含第 1–4 集并保留旧集平台 ID；送审任务只针对新版本。
3. 新版审核中或被驳回时，第 1–3 集仍在线；审核通过且切换线上版本后第 4 集才出现在公开列表并可播放。
4. 重复点击媒资、版本或送审不会重复处理已完成的同一目标；超时结果能对账，不能盲目创建新版本。
5. 新建同名剧集不会覆盖旧剧集；追加模式中冲突集号无法提交。刷新页面可恢复正确的编辑模式。
6. 保存模板、重置表单、应用模板后创建新剧集，彼此不会带入旧剧集 ID、已上传文件或平台任务。
7. 平台任务列表表头与状态列逐行对齐，失败详情不会挤动列宽；窄屏可以横向滚动查看。

## 9. 本次采用的产品口径

- 免费配置按真实集号阈值计算，后台显示为“免费集号上限”；分集单独勾选免费仍然生效。
- 新增分集默认不勾选“单集免费”，以免覆盖剧集级策略；运营人员可手动设置例外。既有分集的单集免费标记不会自动改动。
- 模板只保存通用配置，并存储在当前浏览器；剧名、简介、封面、视频和分集 ID 不进入模板。
- 新版本通过审核后，由运营人员手动设置线上版本；已上架剧集切换成功后按新版快照开放新增分集。

## 10. 实施范围与验证

- 管理 API 已提供按目标剧集 ID 批量追加分集，使用事务检查集号冲突和封面状态，不改写原访问策略。
- 管理后台已提供新建/追加模式、目标剧集选择、模板保存/应用/删除、重置按钮和草稿模式恢复。
- 提交前要求每个新增分集选择视频；本地文件不会写入浏览器草稿，刷新后需重新选择。
- 平台同步沿用旧视频登记结果；新版本使用完整剧集快照，送审按版本去重；旧线上版本在新版本审核期间保持可见。
- 公开分集由线上版本快照控制；未知结果会停止自动重放，要求对账。
- 本地构建、API 回归测试和模拟浏览器操作已通过。真实 TikTok/BytePlus 的上传、审核和切换仍需在有凭据的环境按第 8 节执行人工验收。
