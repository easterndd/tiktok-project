# 匿名观众与进入广告实施方案

## 目标

实现以下两项能力：

1. 用户进入 TikTok Mini 小程序时，根据后台全局配置展示进入广告，并支持设置开关、广告位和观看次数。
2. 小程序不要求用户登录 TikTok，但可以在同一设备上保存观看历史、断点续播、剧集解锁状态和广告行为数据。

## 现状与结论

当前剧集解锁广告已经存在，但不能直接用于进入广告：

- 剧集广告会话绑定 `userId + episodeId`，完成后会创建永久剧集解锁记录。
- 进入广告是全局准入策略，不应关联某部短剧，也不应产生剧集解锁。
- 当前观看历史依赖登录用户的 `WatchProgress`，且播放器只上报首帧和错误，尚未持续调用进度写入接口，因此历史记录尚不完整。

因此，需要分别建设“进入广告会话”和“匿名观众身份”，同时复用现有 JWT、观看进度、广告事件及剧集解锁能力。

## 一、进入广告策略

### 1. 广告类型与平台约束

进入广告应作为独立广告场景，不能默认复用剧集解锁的 Rewarded Placement。

建议后台提供两种模式：

| 模式 | 用途 | 建议 |
| --- | --- | --- |
| `INTERSTITIAL` | 用户进入小程序时展示插屏广告 | 推荐作为默认模式 |
| `REWARDED_GATED` | 用户完成 N 条激励广告后才进入首页 | 仅在 TikTok 明确允许时使用 |

在使用 `REWARDED_GATED` 前，必须以当前 TikTok Minis SDK 和 Portal 广告政策为准确认该场景允许。无论哪种模式，建议单次最多 3 条，并为广告无填充和 SDK 失败配置降级策略，避免用户被永久阻塞。

### 2. 后台配置

新增全局“进入广告”配置页，不放入当前按剧集设置的访问策略中。

```text
AppEntryAdPolicy
- id: singleton
- enabled: boolean
- mode: INTERSTITIAL | REWARDED_GATED
- placementId: string
- requiredCount: int, 1..3
- onUnavailable: ALLOW | BLOCK
- version: int
- updatedAt: datetime
- updatedBy: adminUserId
```

后台需要提供：

- 是否启用进入广告。
- 广告模式：插屏广告或激励门槛广告。
- TikTok Placement ID。
- 每次进入需完成的广告数。
- 广告无填充、SDK 不可用、展示失败时允许进入或阻止进入。
- 保存按钮、修改审计记录和生效版本号。
- 最近 7 天、30 天广告数据：启动次数、请求数、展示数、完成数、关闭数、失败数和进入成功率。

建议将进入广告独立放到运营后台侧边栏的“广告策略”入口；剧集访问策略仍只管理免费集数和单集解锁广告。配置页使用开关、数字输入框和下拉选择，不使用自由文本表达布尔状态。

### 3. 数据模型

不能复用 `RewardedUnlockSession`。新增如下表：

```text
AppEntryAdSession
- id
- viewerId
- launchId
- policyVersion
- placementId
- mode
- requiredCount
- completedCount, default 0
- status: ACTIVE | COMPLETED | ABANDONED | EXPIRED
- expiresAt
- createdAt
- updatedAt

AppEntryAdCompletion
- id
- sessionId
- clientEventId
- adIndex
- adEventId
- createdAt

唯一约束：
- AppEntryAdCompletion(sessionId, clientEventId)
- AppEntryAdCompletion(sessionId, adIndex)
```

`AdEvent` 需要支持广告场景标识，例如：

```text
scope: APP_ENTRY | EPISODE_UNLOCK
```

保留原始 `episodeId`、`rewardSessionId` 等字段，让剧集广告报表不受影响。进入广告的事件不应填写 `episodeId`。

### 4. 接口契约

```text
GET  /app-entry-ad-policy
POST /app-entry-ad-sessions
POST /app-entry-ad-sessions/:sessionId/complete
POST /ad-events
```

建议接口行为：

```text
POST /app-entry-ad-sessions

请求：
{ "launchId": "uuid" }

响应之一：
{ "required": false }
{ "required": true, "sessionId": "...", "mode": "INTERSTITIAL", "placementId": "...", "requiredCount": 1 }
{ "required": true, "sessionId": "...", "mode": "REWARDED_GATED", "placementId": "...", "requiredCount": 2 }

POST /app-entry-ad-sessions/:sessionId/complete

请求：
{ "clientEventId": "uuid", "isEnded": true }

响应：
{ "completedCount": 1, "requiredCount": 2, "shouldContinue": true, "access": "ENTRY_AD_REQUIRED" }
{ "completedCount": 2, "requiredCount": 2, "shouldContinue": false, "access": "APP_PLAYABLE" }
```

服务端必须使用数据库事务、幂等 `clientEventId` 和可串行化事务隔离级别，防止重复回调使一次广告被计数多次。

### 5. 小程序启动流程

进入广告必须阻塞内容首屏渲染，不能只放在首页组件中，否则首页内容会短暂露出。

```text
小程序启动
  -> 读取或创建匿名观众身份
  -> 获取或刷新匿名 JWT
  -> 生成并保存本次 launchId
  -> 创建或恢复进入广告会话
  -> 不需要广告：渲染 Router 与首页
  -> 需要广告：显示全屏 EntryAdGate
  -> 按顺序展示第 1..N 条广告
  -> 每完成一条调用 complete
  -> 完成全部要求：渲染 Router 与首页
```

`launchId` 放在 `sessionStorage`。同一次打开期间刷新页面应恢复已完成状态，不应重复弹广告；关闭小程序并再次冷启动时生成新的 `launchId`，再按后台策略决定是否展示。

前端需要新增：

```text
src/features/ads/app-entry-ad.ts
src/components/EntryAdGate.tsx
```

`EntryAdGate` 应位于 React Query Provider 和路由器的外层或受其直接控制的位置。广告加载、播放和失败均应有明确状态；无填充或 SDK 不可用时严格按后台 `onUnavailable` 决策执行。

## 二、无登录的匿名观众身份

### 1. 设计原则

用户不需要显式登录 TikTok，但后端仍需要识别“同一台设备上的同一位观众”，以保存历史、续播、广告会话和剧集解锁状态。

采用匿名身份，而不是设备指纹：

1. 首次启动，前端生成高随机度 `visitorKey`。
2. `visitorKey` 持久化到 TikTok 小程序可用的本地存储。
3. 客户端发送 `visitorKey` 以交换匿名 JWT。
4. 后端只保存 `visitorKey` 的不可逆哈希，不能保存原始值。
5. JWT 放在 `sessionStorage`；到期后使用 `visitorKey` 自动换取新 JWT。

匿名身份的边界必须明确：用户清除小程序数据、卸载小程序或更换设备后，历史与解锁状态无法恢复。这是“不要求登录”的合理代价，不应通过浏览器或设备指纹规避。

### 2. 用户模型迁移

保留现有 `User` 及其关联表，避免重建观看历史、广告事件和解锁关系。调整为同时支持匿名与 TikTok 身份：

```text
User
- id
- identityType: ANONYMOUS | TIKTOK
- visitorKeyHash: nullable, unique
- tiktokOpenId: nullable, unique
- createdAt
- updatedAt
```

原有与 `User` 的关系无需改动：

```text
WatchProgress
EpisodeUnlock
RewardedUnlockSession
AdEvent
AlbumFavorite
AlbumLike
UserPreference
PlaybackQualityEvent
```

这样，现有受 JWT 保护的接口仍可工作，只是 JWT 的用户主体由匿名初始化接口自动创建，而不是 `TTMinis.login()` 创建。

### 3. 匿名会话接口

```text
POST /auth/anonymous/session
```

请求：

```json
{ "visitorKey": "256-bit-random-value" }
```

响应：

```json
{
  "accessToken": "jwt",
  "expiresIn": 3600,
  "viewer": { "id": "anonymous-user-id", "type": "ANONYMOUS" }
}
```

服务端要求：

- 对 `visitorKey` 施加长度和格式校验。
- 采用 HMAC 或加盐哈希存储，而不是明文或普通可猜测哈希。
- 以 `visitorKeyHash` 查询或创建匿名用户。
- 签发当前已有的 `kind: 'user'` JWT，继续复用 `requireUser`。
- 对接口按 IP、身份和设备节流，防止批量创建匿名用户。

### 4. 前端改造

新增：

```text
src/features/auth/anonymous-session.ts
```

它负责：

- `getOrCreateVisitorKey()`。
- `ensureAnonymousSession()`。
- 启动时、JWT 不存在时、收到 401 时自动恢复会话。
- 通过单一 Promise 去重并发的初始化请求。

删除或移除用户路径中的 TikTok OAuth 依赖：

- 删除用户触发的 `loginWithTikTok()`。
- 删除资料页中的“使用 TikTok 登录”按钮。
- 点赞、收藏、剧集广告解锁前不再要求登录，而是先确保匿名会话。
- 资料页改为“观看记录”和“本机设置”，不要展示账户资料或跨设备同步承诺。

TikTok Mini 的 Client Key 仍需保留，用于 TikTok SDK、播放器和广告初始化；只是用户身份不再依赖 TikTok OAuth。部署后必须继续使用真实 Client Key，不能包含占位文本。

## 三、观看历史与断点续播

### 1. 现有缺口

后端已具备：

```text
PUT /me/watch-progress
GET /me/watch-progress
GET /me/history
GET /home
```

但播放器目前只记录首帧和播放错误，未持续调用 `PUT /me/watch-progress`。因此必须先补全前端播放进度采集，否则匿名身份建立后也无法得到可靠历史。

### 2. 上报规则

播放器适配层应在以下时机调用进度接口：

| 时机 | 操作 |
| --- | --- |
| 有效播放超过 5 秒 | 创建第一条历史记录 |
| 每 10-15 秒 | 同步当前位置 |
| 进度变化超过 5 秒 | 提前同步一次 |
| 暂停、切后台、切换剧集、组件销毁 | 立即同步 |
| 接近片尾或 SDK 播放结束事件 | `completed: true`，同步最终位置 |

请求示例：

```json
{
  "episodeId": "local-episode-id",
  "positionMs": 42000,
  "durationMs": 90000,
  "completed": false
}
```

为防止短时间高频写入：

- 以前端节流为主，每 10-15 秒最多一次。
- 页面卸载时使用最佳努力发送，不阻塞离开页面。
- 网络失败时写入小型本地待同步队列，下一次启动或网络恢复后重试。
- 服务端继续校验剧集在线状态、区域可见性和进度不得超过时长。

### 3. 前端展示

完成匿名会话后，现有首页“继续观看”和资料页历史接口可继续使用。

资料页建议改为：

- 标题：“观看记录”。
- 展示最近观看剧集、集数、观看进度和继续播放入口。
- 提供“清除本机观看记录”操作；该操作需二次确认，并同时删除本地 `visitorKey`、JWT 和服务端匿名用户数据或按隐私策略申请删除。
- 本机偏好可继续保存语言、自动播放和省流模式。

## 四、剧集解锁广告的兼容方式

匿名 JWT 与现有 `requireUser` 兼容，因此当前“观看广告解锁剧集”的核心逻辑可以保留：

```text
匿名用户
  -> 创建 Episode Reward Session
  -> 播放 1..N 条激励广告
  -> 服务端记录 Reward
  -> 创建 EpisodeUnlock
  -> 允许播放剧集
```

需要修改的只是前端入口：

```text
旧逻辑：没有 JWT -> TTMinis.login() -> 解锁
新逻辑：没有 JWT -> ensureAnonymousSession() -> 解锁
```

进入广告与剧集解锁广告必须使用不同会话表、不同广告场景和不同 Placement ID，避免进入广告错误解锁任意剧集，也避免剧集解锁广告被计入启动广告报表。

## 五、实施拆分

### 阶段 1：匿名身份基础

1. Prisma 迁移：扩展 `User` 支持 `ANONYMOUS` 身份与 `visitorKeyHash`。
2. 新增 `/auth/anonymous/session`，签发匿名 JWT。
3. 前端新增匿名会话管理器，在应用启动前初始化。
4. 移除 Mini Web 中用户侧 TikTok OAuth 登录入口。
5. 将现有点赞、收藏、广告解锁操作改为确保匿名会话。
6. 更新隐私政策中的身份、历史与广告数据说明。

### 阶段 2：观看历史与续播

1. 为 TikTok Player 适配真实的播放进度、暂停、结束和销毁事件。
2. 在 `PlayerShell` 或独立 `watch-progress` 模块中实现节流、失败重试和最终同步。
3. 验证 `/me/history`、首页 `CONTINUE_WATCHING`、`resumePositionMs`。
4. 修改资料页为匿名观看记录与本机设置页面。

### 阶段 3：进入广告后端与后台

1. 创建 `AppEntryAdPolicy`、`AppEntryAdSession`、`AppEntryAdCompletion` 迁移。
2. 增加运营后台 API：读取、更新策略，读取广告漏斗数据。
3. 增加后台“广告策略”页面和审计记录。
4. 扩展广告事件，区分 `APP_ENTRY` 与 `EPISODE_UNLOCK`。
5. 为会话创建、重复完成、过期、并发创建和策略变更编写 API 测试。

### 阶段 4：进入广告前端

1. 实现 `EntryAdGate` 和进入广告会话客户端。
2. 实现插屏与激励模式的 SDK 适配。
3. 实现完成、关闭、失败、无填充、超时状态。
4. 让 `EntryAdGate` 在内容路由渲染前完成决策。
5. 在 TikTok Preview 中验证真实 SDK 行为与 Portal Placement 配置。

## 六、验收标准

### 进入广告

- 后台关闭进入广告后，冷启动直接进入首页。
- 后台开启进入广告并设置为 N 条后，冷启动须按顺序完成 N 条才进入内容页。
- 刷新同一次打开的小程序不会重复弹广告。
- 关闭小程序后再次打开，会生成新的启动会话并重新按策略执行。
- 广告无填充、SDK 不可用、广告展示失败时，严格按后台降级策略执行。
- 同一个广告完成回调重复发送不会增加完成次数。
- 进入广告不会创建剧集解锁记录。

### 匿名身份与历史

- 首次进入无需点击登录即可播放免费内容、解锁内容和写入广告事件。
- 播放超过 5 秒后，历史页与首页“继续观看”出现该剧集。
- 重启小程序后可恢复同一设备的断点续播。
- 清除小程序本地数据后，匿名身份和历史不再恢复。
- 已有剧集激励广告解锁逻辑在匿名身份下正常工作。
- 任何客户端均不暴露 TikTok Client Secret、JWT Secret、数据库密码或第三方私钥。

## 七、上线前检查

1. 在 TikTok Portal 中确认进入广告场景、广告类型和 Placement ID 获得支持。
2. 在 Preview 环境用真实 Client Key、真实生产 API 地址验证 SDK 初始化。
3. 验证 API CORS 已允许 TikTok Preview WebView 的实际 Origin。
4. 验证 TikTok Client Key 与 Mini App App ID 属于同一个 Portal 应用。
5. 验证进入广告和剧集解锁广告的 Placement ID 不重复。
6. 执行数据库备份、迁移演练、回滚演练和 API 自动化测试。
7. 更新隐私政策、数据删除流程和数据保留期限说明。
