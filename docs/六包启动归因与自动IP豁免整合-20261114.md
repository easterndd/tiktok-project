# 六包启动归因与自动 IP 豁免整合

## 范围

本次基于 GitHub main 的 `626e932`，保留 `01b4fdc` 的审核版本自动 IP 入库实现，整合启动归因与入口广告决策。

适用包：ZenClip、StoryWorld、DailyReel、EliteDrama、SonicReel、OrbitPlay。

六包使用 `attr1` 归因协议和各自现有广告位配置；本次不为六包新增未经核准的双广告位。原四个 `v006-dual` 包和其他旧包不切换服务路由。

## 决策顺序

1. 启动时采集本次入口参数，通过匿名会话或 `/auth/launch-context` 保存启动记录，得到服务端 `launchRef`。
2. 用 `appKey + releaseId` 查询共享版本状态。处于 `IN_REVIEW` 时，将服务器识别的当前请求 IP 加入共享豁免表，标记 `AUTO_REVIEW: appKey:releaseId`。重复请求不覆盖已有人工备注。
3. 创建入口广告会话时验证启动记录的用户、小程序、发布号和 launchId，避免串用归因。
4. 再检查审核状态与共享 IP 豁免。命中时立即返回 `required:false / SUPPRESS / IP_EXEMPT`，优先于归因、强弹开关和已有广告会话。已有 `SHOW` 决策也更新为 `SUPPRESS`，保持相同决策 ID。
5. 未命中 IP 豁免时，未归因、参数冲突或无有效启动记录均不强弹。
6. 已归因且未豁免的用户，继续执行该 releaseId 的入口开关、用户豁免、次数和计数模式。

| IP 命中 | 本次启动归因 | 入口策略开启 | 结果 |
| --- | --- | --- | --- |
| 是 | 任意 | 任意 | 不强弹，IP_EXEMPT |
| 否 | 未归因 | 任意 | 不强弹，UNATTRIBUTED |
| 否 | 冲突或无有效记录 | 任意 | 不强弹，归因原因说明 |
| 否 | 已归因 | 否 | 不强弹，POLICY_DISABLED |
| 否 | 已归因 | 是 | 按配置强弹，用户级豁免仍生效 |

“走未归因用户配置”指入口广告处理结果相同，不篡改来源数据。真实已归因用户仍保存为 `ATTRIBUTED`，广告决策另存 `IP_EXEMPT`，便于分析豁免流量来自哪个小程序、发布号和投放参数。

## 状态、存储与边界

- `MiniAppCodeRelease` 在共享数据库保存 appKey、releaseId 和人工维护的 `IN_REVIEW`（审核中）或 `RELEASED`（投放中）状态。尚未登记状态的构建默认为 `UNKNOWN`，不会自动采集 IP；它不是新增的业务状态。
- `SharedEntryAdIpExemption` 在共享数据库按标准化 IP 唯一保存，全局生效。备注记录首次自动来源；同一 IP 后续跨包访问仍可由 `SharedIpVisit` 关联来源，不重复创建豁免行。
- 从审核中改为投放中后，停止为该发布号新增豁免；原豁免继续保留。审核期间所有访问 IP 都会被收集，不能据此认定它们一定属于审核人员。
- `MiniAppLaunch` 在各包数据库保存真实归因；`MiniAppEntryAdDecision` 保存最终广告决策、原因和关联启动。既有启动归因与决策埋点继续使用。
- 对归因协议请求直接读取共享豁免与版本状态，避免跨容器缓存导致状态更新延迟。共享检查故障返回 `IP_CHECK_UNAVAILABLE` 并暂不强弹，不将临时故障固化为永久决策。
- 已下发给客户端并正在执行的广告不会被服务器主动中断。下一次入口决策请求或新启动将应用最新豁免。
- 此次不修改剧集解锁、剧集插屏或退出挽留规则。退出挽留原有的 IP 豁免行为保持现状。
- 无 Prisma schema 变更，不执行数据库迁移；仅为新发布号新增独立策略行。保留旧发布号和 default 策略。

## 验收与发布步骤

1. 本地 API 回归 301 项通过、1 项跳过；前端 125 项通过；API 生产构建及六包 `ttdx minis check`、发布身份校验通过。
2. 以提交版本创建隔离镜像，沿用六包服务配置，备份当前 Caddy、环境和新旧版本策略。保留旧容器以便回退。
3. 验证六包已有表结构，将各自旧发布号策略复制为新 releaseId，其他策略不变。
4. 切流前用真实数据库验证：已归因强弹、未归因不强弹、IP 覆盖已归因、同一启动决策覆盖、跨包豁免、审核中自动入库与重复访问、投放中停止收集但保留旧豁免。测试只用专用测试版本与文档保留 IP。
5. 只切换 Caddy 的六包 upstream；原地写配置保留 inode，校验、reload、HTTPS 验收，失败恢复备份。
6. 切流后验证六包登录、启动归因、入口决策、埋点与后台查询，抽查其他旧包；核对数据库决策与旧策略哈希，检查新容器错误日志。
7. 将新 ZIP 上传到各自 TikTok Portal。提交审核前将准确的新 releaseId 设为“审核中”，审核后改为“投放中”。审核中测试设备自身 IP 也会进入全局豁免，之后带广告参数仍应不强弹；验证正常归因强弹应使用未豁免的网络。

接口与数据库验收不能代替 Android/iOS 原生广告真机展示验收。本次不自动操作 TikTok Portal。
