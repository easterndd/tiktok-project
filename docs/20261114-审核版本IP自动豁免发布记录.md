## 1. 本次变更

| 位置 | 变更 |
| --- | --- |
| `apps/api/src/services/shared-ip.service.ts` | 新增 `exemptIpForReviewRelease` / `ensureEntryAdIpExemption` / `isReleaseInReview` / `invalidateReviewReleaseStatusCache` |

行为：`MiniAppCodeRelease.portalStatus = 'IN_REVIEW'` 时，访问该 `releaseId` 的客户端 IP 写入 `SharedEntryAdIpExemption`，备注 `AUTO_REVIEW: <miniAppKey>:<releaseId>`，操作人 `system:review-release`。同一 IP + 版本 10 分钟内只写一次；`ON CONFLICT DO NOTHING` 不覆盖后台手工配置的备注与操作人。

## 7. 功能验证（DramaFlicks 预览包）

### 7.1 构建预览包

```bash
cd /path/to/tiktok-project
export VITE_API_BASE_URL='https://api.evergreenprosper.com/api/v1'
export VITE_TIKTOK_CLIENT_KEY='<DramaFlicks Portal Client Key>'

```

记下 `releaseId`（形如 `dramaflicks-v006-dual-20261114T...`），下面记作 `<RELEASE_ID>`。

### 7.2 让「不弹」可被证明

新 `releaseId` 首次观察时策略是禁用状态，本来就不会弹，无法证明豁免生效。先给该版本开启入场强弹：

1. 后台「广告配置」→「提前登记构建包 ID」填 `<RELEASE_ID>` →「登记构建包」。
2. 选中该构建包，把入场广告设为启用（策略参数与当前线上主版本一致），保存。
3. 同一面板把 Portal 状态改为 `In review`，保存。

此时正常情况下打开该包会弹入场强弹。

### 7.3 真机验证

用 TikTok 扫码打开该预览包，然后：

```sql
-- 后台「广告配置」页的豁免列表，或直接在共享库查
SELECT "ipAddress", "note", "updatedBy", "createdAt"
FROM "SharedEntryAdIpExemption"
WHERE "note" = 'AUTO_REVIEW: dramaflicks:<RELEASE_ID>';
```

验收点：

| 检查 | 期望 |
| --- | --- |
| 豁免表记录 | 出现一行，`ipAddress` 是你手机出口 IP，`updatedBy = system:review-release` |
| 本次启动 | 不弹入场强弹，直接进内容 |
| 剧集解锁广告 | 仍按原策略正常弹（豁免只影响入场强弹） |
| 重复刷新 | 10 分钟内不重复写入，仍只有一行 |

对照实验（可选但建议）：把状态改回 `Released`，等 30 秒（多实例缓存），换设备或清缓存再打开同一包 → 应恢复弹入场强弹。

### 7.4 验证收尾

```sql
-- 1. 状态改回，避免后续启动继续写入
UPDATE "MiniAppCodeRelease"
SET "portalStatus" = 'RELEASED', "updatedAt" = now()
WHERE "miniAppKey" = 'dramaflicks' AND "releaseId" = '<RELEASE_ID>';

-- 2. 删除本次验证写入的豁免行
DELETE FROM "SharedEntryAdIpExemption"
WHERE "note" = 'AUTO_REVIEW: dramaflicks:<RELEASE_ID>';
```

后台「广告配置」页也可直接删豁免行、改状态；SQL 只作为兜底。改完状态后 30 秒内缓存失效，期间新启动可能不再写入。

## 9. 已知限制

1. 审核窗口内访问该 `releaseId` 的所有 IP 都会被豁免，不止审核员。
2. 版本离开 `IN_REVIEW` 后，已写入的 `AUTO_REVIEW:` 行不会自动删除，需手工或定期 SQL 清理。
3. 审核状态有 30 秒进程内缓存；仅当状态经后台接口修改时立即失效，直接改库最多延迟 30 秒。

### 10.5 已验证（容器内真实链路）
